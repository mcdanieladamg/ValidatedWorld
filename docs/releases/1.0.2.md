# ValidatedWorld 1.0.2

The plugin listing now describes the skill's purpose: graph-wide conceptual
consistency beyond an agent's context window, with targeted retrieval and
batched reviews by fresh sub-agents before changes propagate.
It also highlights the human-friendly HTML file for browsing the graph.

- Simplify the public listing and bundled introduction around what users can do.
- Use `validated-world` as the package identifier and **ValidatedWorld** as the
  display name. Remove migration suffixes from the source layout, archive names,
  build tools and installer.
- Recommend English for stored workflow guidance rather than requiring it,
  consistently in the skill and command help.
- Keep project working state, SQLite transactions, review packets and approvals
  in memory. Ordinary skill use creates no temporary folders, DBs, response logs,
  review files, lock sidecars or staging files.
- Keep native persistent pipes as the default; add optional in-memory loopback
  command and read-only packet transports for hosts that support them.
- Save directly to the selected HTML after complete review. Unsaved work is lost
  with the process; an interrupted save can leave partial HTML. Existing 1.x
  documents, explicit DB authority and review/batching gates remain supported.

Validation includes 166 passing unit tests with 90% branch coverage and isolated
create/read/review/save workflows that deny every filesystem write except the
selected HTML. Tests cover stale approval, bounded packet delivery, supplemental
context, refinement/synthesis, RAM rollback and failed direct saves.
Both archives passed isolated package and Windows temporary-path alias checks.
A live two-branch review with fresh reviewers and independent synthesis saved
and verified a garden graph without work files; browser navigation also passed.
